# 密评 Skill 落地计划

## 1. 目标

基于已批准设计文档，落地一个面向“应用和数据安全”的密评 Skill。该 Skill 的职责是定义密评标准、检查口径、输出格式和 LLM 行为边界，用来指导 Agent 在审阅代码仓库时应该关注什么、如何判断、如何输出，以及哪些事情不能做。

这个 Skill 不负责：

- 实现扫描脚本
- 编写仓库解析器
- 调用外部模型
- 渲染执行时报告引擎

## 2. 交付物范围

首版交付物只包含文档和模板：

1. `SKILL.md`：Skill 主说明，定义用途、适用范围和使用方式。
2. 评测标准清单：定义四大风险域的检查点与判定规则。
3. LLM 行为约束：明确应该做什么、不应该做什么。
4. 输出模板：定义 Findings 结构和 Markdown/HTML 报告要求。
5. 示例：给出示例提示词、示例 Findings、示例报告片段。

## 3. 落地阶段

### Phase 1：Skill 主文档

目标：先把 Skill 的身份、边界和使用方式定义清楚。

任务：

1. 编写 `SKILL.md`。
2. 明确 Skill 只负责标准定义，不负责执行实现。
3. 写清适用场景、输入前提、输出预期。
4. 写清不适用场景和边界限制。

完成标准：

- Agent 读完 `SKILL.md` 后，知道该 Skill 用来做什么。
- Agent 不会把 Skill 误解为扫描脚本或执行工具。

### Phase 2：评测标准清单

目标：把密评检查口径固化成可复用标准。

任务：

1. 按四大风险域组织检查点：数据加密、鉴权与访问控制、通信安全、国密适配线索。
2. 为每类检查点定义：关注对象、触发条件、风险判断、整改建议方向。
3. 定义风险等级口径。
4. 定义人工复核触发条件。

完成标准：

- 每类问题都有明确检查项。
- Agent 可以据此逐项审阅仓库。

### Phase 3：LLM 行为约束

目标：防止 Agent 在使用 Skill 时越界推断或伪造证据。

任务：

1. 定义“应该做什么”：基于已读文件判断、附带证据、区分事实与推断。
2. 定义“不应该做什么”：不得虚构实现、不得引用未读文件、不得把证据不足当作无风险。
3. 定义“何时必须标记人工复核”。
4. 定义“何时只能给建议，不能给结论”。

完成标准：

- Agent 的行为边界清晰。
- 高风险结论必须附带充分依据。

### Phase 4：输出模板

目标：统一 Agent 使用 Skill 后的输出格式。

任务：

1. 定义 Findings 结构。
2. 定义 Markdown 报告结构。
3. 定义 HTML 报告结构要求。
4. 定义人工复核项、附录、抑制项的表达方式。

完成标准：

- Agent 可以按统一格式输出报告。
- Markdown 与 HTML 的信息结构一致。

### Phase 5：示例与说明

目标：让 Skill 更容易被复用和正确执行。

任务：

1. 提供一个示例提示词，展示如何让 Agent 按 Skill 审阅仓库。
2. 提供示例 Findings。
3. 提供示例 Markdown/HTML 报告片段。
4. 提供常见误用说明。

完成标准：

- 新的 Agent 使用者可以直接参考示例上手。

## 4. 建议目录结构

```text
agent-skills/
  guomi-app-data-security/
    SKILL.md
    README.md
    standards.md
    output-template.md
    examples.md
```

这个目录结构体现的是“规则与模板”的组织方式，而不是可执行程序结构。

## 5. 实施顺序建议

1. 先写 `SKILL.md`，定清楚边界。
2. 再写评测标准清单。
3. 再写 LLM 行为约束。
4. 最后写输出模板和示例。

这个顺序的原因是：如果边界不先定清楚，后面的标准、模板和示例很容易再次滑向“在 Skill 里实现工具”的错误方向。

## 6. 风险与应对

- 风险：Skill 写成工具设计文档。
  应对：所有文档都反复强调“只定义标准，不实现执行器”。

- 风险：规则太泛，Agent 执行时仍然自由发挥。
  应对：为每类风险定义明确触发条件、结论边界和输出要求。

- 风险：报告格式不统一。
  应对：提供固定 Findings 模板和报告模板。

## 7. 完成判据

当满足以下条件时，认为首版 Skill 落地完成：

1. Skill 文档明确说明职责边界。
2. 四大风险域均有明确评测标准。
3. LLM 的行为约束清晰，包括应该做什么和不应该做什么。
4. 输出模板完整，支持 Markdown 和 HTML 两种格式。
5. 提供足够示例，能够指导 Agent 正确使用该 Skill。
