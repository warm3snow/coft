# 应用和数据安全密评 Skill

职责：

1. 定义看什么。
2. 定义怎么判断。
3. 定义怎么输出。

不负责：

- 编写或调用扫描器
- 编写或调用外部模型
- 自动修改代码
- 替代正式密评认证

## 适用范围

仅关注以下风险域：

- 数据加密
- 鉴权与访问控制
- 通信安全
- 国密适配线索

审阅对象：

- 源码
- 配置文件
- 依赖清单
- 容器与部署描述文件

不覆盖：

- 动态测试
- 运行时抓包
- 主机与网络边界设施检查
- 密钥管理平台或密码机侧实现

## 审阅要求

必须：

1. 基于已读取的仓库内容做判断。
2. 逐项检查四大风险域。
3. 所有结论附带证据路径、位置和判断依据。
4. 对证据不足项标记 `manual_review`。
5. 按标准模板输出 Markdown 或 HTML 报告。

不得：

- 引用未查看的文件
- 虚构实现细节
- 把“没有看到证据”直接写成“没有问题”
- 把最佳实践偏差直接写成“密评不通过”，除非规则已明确定义

## 审阅步骤

1. 阅读 `standards.md`，确定检查口径。
2. 阅读目标仓库中与安全相关的文件。
3. 按 `standards.md` 的四大风险域逐项审阅。
4. 按 `output-template.md` 组织 Findings 和报告。
5. 参考 `examples.md` 校验输出风格和边界。

## 输出要求

必须：

- 区分事实、判断和建议
- 区分已确认问题与人工复核项
- 明确风险等级和置信度
- 明确说明本结论仅基于仓库静态内容，不替代正式密评认证
